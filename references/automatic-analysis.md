# 默认完成采集与分析

用户要求采集并生成研究报告时，Agent 默认继续完成初步分析，不要求用户再说一次“分析这些词”。只有用户明确“只采集/只要原始表”时才跳过。资料不足不阻塞词条层面的研究方向；对具体商品的卖点、参数、配方、适用人群和承诺不得推测。

## 执行顺序

1. 原始采集、截图及Excel保持独立，不修改原词来凑分析。
2. 运行 research_project.py 生成同一入口。渲染器自动调用 analyze_research.py，为每个根词/批次生成词面规则初步分析、来源词、待验证资料与截图链接；旧项目重复导入不新增批次，但会重建报告以应用新模板。
3. Agent 阅读本轮完整去重词，按用户目标检查分组和建议，识别共同问题、具体内容切口、商品页遗漏及客服疑问。默认主动完成，不把一条“请再让我分析”的提示词当作交付。
4. Agent主动将综合解读写入项目内 `agent-analysis.json`，再运行同一 research_project.py 更新原HTML，不另建页面。格式为 `{批次ID: {词根: [卡片]}}`，批次ID从research-project.json读取。卡片字段为 title、finding、action、verification（非空文本）及 source_terms（实际原词列表）。每个词根结合实际数据提炼有用方向，不机械凑固定条数。渲染器严格验证原词属于该词根与批次，自动接上截图；越界或缺字段时拒绝更新。分析与原始capture分开，禁止直接更改原词、编写截图URL或把别批资料混入。未做综合解读时先有规则初步分析，但不能把仅完成规则导出当成Agent研究任务已全部完成。
5. 检查根词和批次切换后，建议与对应词条一致；失败批次不能替换此前完整数据或分析。无有效词时显示无可分析数据，不编造建议。

规则采用跨类目的有限词面分类，不把烘焙参数写成通用方法论；未覆盖词标待进一步判断，仍输出具体原词供后续分析。类别词数是本批覆盖，不是需求规模或商业价值排名。排名、无添加、特殊人群或健康表述仅作核查线索。
